# 0.8 解耦版 — 为 0.9 上云预拆接缝

> 状态：定稿 2026-07-14。0.8 **不做 TTS**（TTS + 原片字幕已挪 2.0）。0.8 = 把该拆的接缝拆出来，为 0.9 商业化上线做准备。**验收标准：`DEPLOYMENT_MODE=local` 下端到端行为与拆分前零差异（纯解耦、无回归）。**

## 一、商业模型（锁定）

平台**只提供两项付费服务**，其余全部用户 BYOK：

| 能力 | 谁提供 | 谁付费 | 在哪跑 |
|---|---|---|---|
| **视频生成** | 平台（Seedance 中转） | 用户买 credits | 云端网关 → 火山（企业 key 只在云端） |
| **agent 能力** | 平台（秘密 prompt = 护城河） | 用户订阅 / 授权 | 云端 `/v1/agent/run`，用**用户转发的 LLM key** 跑 |
| LLM | 用户自己（BYOK） | 用户自己 | 本地配 key；调 agent 时随请求转发上云、用完即弃 |
| 生图 / 音频 | 用户自己（BYOK） | 用户自己 | 全本地，平台不碰 |

**agent 上云走 Y（关键决策）**：agent 逻辑/prompt 在云端，用户的 LLM key 本地存、**按调用转发上云、用完即弃**（TLS、云端只在内存里用那一次、不落库）。
物理约束：一次 LLM 调用需 prompt + key 在同处碰头。agent 在云端 → key 必须转发（否则 prompt 下发本地 = 泄漏）。"配置留本地" = 用户拥有/管理/付费（BYOK 本意），非"字节永不上云"。

## 二、部署模式开关

`config.py: DEPLOYMENT_MODE`（env `OCTOPUS_DEPLOYMENT_MODE`）：
- `local`（默认）：全本地，现状，行为零变化。本地开发/自用永远用它。
- `cloud_client`：上线态——视频走云端中转、agent 走云端服务、企业 key 不下发本地。

0.8 只建"按此开关分叉"的接缝；`cloud_client` 的**云端实现（网关、agent 服务、STS 签发、支付、Redis 队列）留到 0.9**。

## 三、两个云端服务端点（0.9 建，0.8 只留客户端插口）

- `POST /v1/video/generate` — 视频中转：验 token → 查余额 → 用平台企业火山 key 转发 Seedance → 按秒计 credits → 回视频 URL（**字节不过服务器**，客户端直连火山/OSS 下载）。
- `POST /v1/agent/run` — agent 即服务：`{agent_type, input_context, llm_config(用户key转发), token}` → 验 token/entitlement → 加载该 agent 的**秘密 prompt（只在云端）**→ 用转发的 llm_config 调 LLM → 解析 → **只回结构化 JSON**（prompt 从不下发，key 用完即弃）。

### ✅ 缝2 —— 视频数据面抽象（2026-07-21 完成，已验收）

**核心产物：`app/core/media_gateway.py`** —— "把本地媒体变成厂商能取到的 URL"的统一入口，按部署模式分叉：

**两条铁律（写进模块 docstring，改之前先读）**
1. **远程 http(s) URL 默认原样透传，绝不重新托管**（`rehost_remote=False` 是默认）。Seedance 真人审核靠"同账号信任产物"放行——关键帧必须是火山原始 TOS URL，一旦下载重传到我们的 OSS 就变第三方图、写实人脸重新被拦 = 生产阻断。**唯一例外** `register_asset` 用 `rehost_remote=True`（火山 origin_url 24h 过期，蚂蚁异步下载会 403）。
2. **拿不到公网 URL 回退 base64，不硬失败**（OSS 没配的开发机要能跑）。例外：视频翻译要真·公网成片，用 `to_public_url` + 保留硬失败。

| 改动 | 落点 |
|---|---|
| 新建数据面 | `core/media_gateway.py` |
| Seedream 多图参考 | `image_to_image.py` —— 手写的 try-OSS-else-base64 去重（单图仍走 base64，省一次往返，行为不变） |
| 蚂蚁 asset 入库 | `_antchain_video.register_asset` —— `rehost_remote=True`；顺带修掉"OSS 配了但上传失败时把**本地路径**当 URL 发出去"的老 bug |

**⚠️ local 模式下唯一的行为变化（✅ 2026-07-21 已实跑验证）**：本地媒体作首帧时，从「base64 塞 payload」变成「传 OSS 拿 URL」。
- 远程 URL（火山 TOS 关键帧）**完全不受影响**——透传，信任模型原样保留。
- 只影响本地文件那条路；本地文件本来就不是火山信任产物（base64 也不是），所以不损失审核豁免，反而免掉大 base64 撑爆请求体 + Seedream 5.0 多图不认 base64 的老问题。
- 本机实测数据面可用（`local_oss`），故该变化对当前配置**是生效的**。

**首帧用 `public=True`（无签名干净 URL，走 CDN 域名 `<你的CDN域名>`）—— 2026-07-21 实跑后定的**
签名 URL 有两个坑：① **1h 有效期**，视频任务排队久了厂商去抓首帧就 404；② query 串（`?...Signature=...%3D`）有被厂商网关弄坏的先例（蚂蚁 IMS → `MaterialNotExist`）。干净 URL 两个都没有。
代价 = 对象 public-read，但 key 是 uuid4、URL 猜不到，且**成片本来就在用同一条通道**，关键帧敏感度更低。
**Seedream 多图参考那条路保持签名 URL 不动** —— 它 0.7.3 起就在生产用签名 URL 且工作正常（这也反证**火山能正确处理签名 query 串**，所以真正的风险只是过期，而图片生成没有长队列）。

**实跑验证**（`_verify_seam2_live.py`，仓库根，用真实 OSS 凭据真传真取，不调用任何视频生成接口）：
本地首帧真的不再走 base64；真实上传 0.66s / 699KB；**站在厂商视角 GET 该 URL → HTTP 200 · `image/png` · SHA256 与本地完全一致**；payload 从 base64 的 932KB 降到 197 字节（≈4800x）；火山 TOS URL 原样透传未被改写；i2v 真正调用的 `_prepare_image_url` 产出 `https://<你的CDN域名>/...`（无 query 串）且可下载、字节一致。

**验收**（`_verify_seam2.py`，仓库根，mock 后端不碰真 OSS）：远程透传时 `put_remote` 零调用、`rehost_remote=True` 确实重传、本地文件→URL 且不再 base64、`public=True` 透传、数据面不可用→base64 兜底且 `to_public_url` 返 None、cloud_sts stub 不崩只回退、首帧两个调用链实测走数据面且缺文件仍抛 ValueError。另重启后端零 import 错误、`_verify_seam3.py` 重跑仍 ALL PASS。

#### 🔴 实现时更正了原方案的插口位置（重要）

原方案把插口定在 `base_agent.llm_chat`。**那里保护不了 prompt**：

- 护城河的实际所在 = 各 agent 文件里的**模块级 prompt 常量（实测 ~4 万字）** + 体量更大的**拼装逻辑**（`director_agent.py` 79KB / `storyboard_agent.py` 85KB，绝大部分是 prompt 工程）。
- 执行流到 `llm_chat` 时 prompt 早已拼好躺在 `messages` 里；而那些 `.py` 本来就随桌面端分发到用户机器。
- 所以在 `llm_chat` 分叉 = **护城河照发不误，只是多绕一次云端**，一点没护住还多一跳延迟。

**正确插口必须在拼 prompt 之前 = agent 的两个入口**：`run()`→`execute()`（主生成）与 `chat()`（对话式修改，`_chat_system_prompt()` 同样是护城河）。

**成立前提（已核查全部 9 个 agent）：agent 都是纯函数** —— 零文件 IO、零 DB、零 module 调用，纯粹 `task/context → 拼 prompt → LLM → 解析 JSON → dict`。所以整个 agent body 可以整体搬到云端，本机只留一个 HTTP 调用。这正是路 A。

#### 0.9 要填的端点契约（已写进模块 docstring）

    POST {gateway}/v1/agent/run
      body: {agent_type, entry: "execute"|"chat", payload, llm_config:{provider,api_key,base_url,model}}
      → {ok, data, usage?, error?}

`llm_config` = **用户 BYOK key，转发即弃**（商业模型"走 Y"）。物理约束：一次 LLM 调用要 prompt + key 在同处碰头；prompt 在云端 → key 必须转发。`data` 直接是 agent 的返回 dict（解析也在云端做完），本机拿到即用。
网关/token 复用 `octopus_cloud_config()`（同一个平台账号，不另立一套设置字段）。

**验收**（`_verify_seam0.py`，仓库根）：用探针 agent 记录本地是否碰过护城河。
local 下 `execute`/`_build_chat_prompt`/`_chat_system_prompt` 照常被调用（零回归）；**cloud_client 下这三个一次都没被调用**（= prompt 没在本地成型，插口位置正确）；配置缺失给可操作报错且 `run()` 返回 `AgentResult(success=False)`、`chat()` 返回友好 dict 而非抛异常；BYOK `llm_config` 取值路径通；`usage` 回填 `_last_usage`（缝6 计量口）；切回 local 行为立刻恢复。

### ✅ 缝4 —— entitlements 能力门控（2026-07-21 完成，已验收）

**核心产物：`app/core/entitlements.py`** —— `Capability` 常量 + `check()` / `require()` / `deny_reason()` / `status()`。
`local` = **全放行 no-op，连授权都不读**（零回归、零开销）；`cloud_client` = **fail-closed**，校验本机存放的 Ed25519 签名授权。

**与缝0/缝1 的 stub 不同，这条的校验逻辑 0.8 就写完整了** —— 验签是纯本地密码学（公钥内置），不需要云端在线；云端只负责**签发**。0.9 只补两件事：① 真实公钥 ② 签发/购买流程。

授权凭据（存 `user_settings("license","token")`）：

    {"payload": {"sub", "plan", "caps": [...], "exp"}, "sig": "<base64 Ed25519>"}

签名对象 = payload 的 **canonical JSON**（`sort_keys=True, separators=(',',':')`）。**签发端必须用同样的序列化方式**，否则验签必失败。

| 门控点 | 能力 | 失败语义（沿用各自既有约定，不改调用方） |
|---|---|---|
| `batch_execute_nodes` | `video.generate` | 返回 `{"type":"entitlement_denied","message":...}`，**不抛异常**（该方法本来就返回结构化 dict） |
| `_run_audio_plan` / `_post_audio_plan` / `_run_episode_audio_plan` | `audio.generate` | 抛 `EntitlementError` → 节点转 FAILED |
| `_run_localization` | `video.localize` | 返回 error result（该方法约定"失败不阻断"） |
| `_fanout_storyboard` | `storyboard.fanout` | 抛 `EntitlementError`（可选闸：扇出不花钱，但拦在这比等批量生成再拒更早） |
| `agent_runtime.run_remote` | `agent.run` | 抛 `EntitlementError`（agent 订阅 = 两项付费服务之一） |

**拒绝话术分级**（别一律 "denied"）：没授权 → "需要登录并订阅"；验签失败/过期 → "授权无效或已过期，请重新登录/续订"；有授权但套餐不含 → "当前套餐不包含「X」，请升级"。

**验收**（`_verify_seam4.py`，仓库根，脚本内自建 Ed25519 密钥对跑通完整签发→验签闭环）：
local 下 5 项能力全放行、**塞一张故意损坏的授权也毫无影响**（证明压根没读）；cloud 下无授权 fail-closed；有效授权验签通过且套餐外能力被拒；**过期被拒 / 篡改 payload 验签失败 / 他人公钥签发被拒**；6 个门控点实测拦在方法第一行（用未初始化的 executor 实例调用，证明门控先于业务状态）；agent 门控放行后落到下一层错误；切回 local 立刻恢复。

> 🔎 **跨缝回归实录**：加完本条后 `_verify_seam0.py` 立刻挂了 —— `run_remote` 前面多了订阅门控，缝0 原本"缺网关 → ValueError"的预期被 `EntitlementError` 顶掉。**新行为是对的**（没订阅就该先拦订阅），于是改用例：缝0 测试先发一张 `agent.run` 授权放行门控，再测下层配置校验。这正是"每加一条缝都重跑前面全部"的价值。

### ✅ 缝5 —— 账号 / token 管道（2026-07-21 完成，已验收）

**核心产物：`app/core/identity.py` + `app/api/auth.py` + 前端拦截器。**

拆分前是"零鉴权 + 假登录"：`LoginPage.tsx` 任意非空即通过、把 `mock_xxx` 写进 localStorage，而 `api.ts` **从来不发这个 token**，后端也没有 auth 中间件。0.8 把管道接通，两头结构对齐，0.9 换真实云端登录时不用再改结构。

| 改动 | 落点 |
|---|---|
| identity 抽象 | `core/identity.py`：`current_user_id()` / `cloud_token()` / `set_session()` / `clear_session()` / `require_cloud_token()` / `get_current_user()` 依赖 / `status()` |
| 账号 API | `api/auth.py`：`GET /api/auth/status`、`POST /api/auth/login`、`POST /api/auth/logout`（已挂进 `main.py`） |
| token 单一真相 | `octopus_cloud_config().token` 改从 `identity.cloud_token()` 取 —— 统一了缝1 的手填 token 与缝5 的登录态 |
| 前端 | `api.ts` 加请求拦截器统一附 `Authorization: Bearer`（导出 `TOKEN_KEY` + `authAPI`）；`LoginPage.tsx` 改调后端，token 由后端签发 |

**本地后端为什么不加鉴权**：它跑在用户自己机器上、单机单用户，加多租户鉴权没有意义（用户对自己的后端天然有完全权限）。真正需要 token 的是**出站方向**：本机 → 云端网关。所以这条缝的重点不是"验别人的 token"，而是"**持有并转发我自己的 token**"。`get_current_user()` 在 local 下**忽略 Authorization** 恒返回 `LOCAL_USER`。

**token 兼容**：以 `account.token`（登录写入）为准，缝1 的手填 `video.octopus_cloud_token` 作兜底保留 —— 已经填过的用户不受影响。

**local 登录语义与拆分前一致**：任意非空账号密码通过。差别只在判断挪到后端、会话有真实落点（`issue_local_token()` 明确标注**不是安全凭据**，只是让"已登录"有个来源）。cloud_client 登录回 **HTTP 501 + 可读话术**，不假装成功。

**验收**（`_verify_seam5.py` + 真实 HTTP 实测）：local 恒 `LOCAL_USER` / 恒已认证；token 优先级（account 优先、legacy 兜底）；`octopus_cloud_config` 与 `agent_runtime` 拿到同一个 token；login/logout/400/501 语义；local 下带伪造 Bearer 仍返回 `LOCAL_USER`；`status()` 不泄露 token 本体。
实测 `GET /api/auth/status` → `{"mode":"local","authenticated":true,...}`、`POST /login` 签发 `local.laobai.<ts>`、空账号 400、logout ok；**带 Bearer 打既有端点仍 HTTP 200**（拦截器零影响）。

> ⚠️ **顺带发现（既有问题，非本次引入）**：`npx tsc --noEmit` 有 **43 个既有类型错误**，分布在 `BatchGenerateButton.tsx` / `FloatingChat.tsx` / `AssetManagerModal.tsx` / `KeyframeEditor.tsx`（本次改的 `api.ts` 与 `LoginPage.tsx` **零报错**）。因为 `npm run build` = `tsc && vite build`，**这些错误会让生产构建失败**；`vite dev` 不做类型检查所以平时无感。0.9 要做桌面端分发前必须清掉。

### ✅ 缝6 —— 计量上报 hook（2026-07-21 完成，已验收）

**核心产物：`app/core/meter.py`** —— `report()` / `pending_count()` / `drain()` / `stats()` / `_flush()`（0.9）。
旁挂在 `_capture_usage_to_cost_log` 的 cost_log 写入**之后**，不动既有逻辑。

这条几乎不用改代码，因为 `usage` dict 本来就是云端计量的完美 payload —— **仪表早就装好了，缺的只是账本**。

**两条铁律**
1. **永不抛异常、永不阻塞**。计量失败绝不能打断用户生成 —— 那一刻钱已经花了、片子已经出了，因为记账失败让节点 FAILED 是纯粹的伤害。所有异常在 `report()` 里咽掉。
2. **只上报视频**（`kind == "video"`）。视频是平台中转、按 credits 计费；LLM / 生图 / 音频是用户 BYOK（自己付钱给厂商），平台不该也没资格记账，它们继续只进本地 cost_log 供用户看成本。

另有 mock 不计费、队列上限 5000（云端没上线时别吃光内存，超出丢弃并计数）。

**验收**（`_verify_seam6.py`）：local 下 4 种 usage 全 no-op（队列恒空）；cloud 下只有视频入队、LLM/图/音频不入队；mock 不计费；**喂 None / 空 dict / 字符串 / 数字 / list / 缺字段 / 含抛异常对象的 usage 一个都不抛**；队列上限与丢弃计数生效；反射校验 `meter.report` 确实挂在 cost_log 之后；切回 local 立刻零开销。

**未做（有意）：执行-job 抽象**。原计划把它作为"整脑上云"（路 B）的插口一并埋。**跳过的理由**：0.9 走的是路 A（agent 即服务），路 B 是"以后可选"；重活 runner（keyframe / video / merge）深嵌在 executor 里，现在为一条未必会走的路径造抽象，等于凭空猜一个接口形状 —— 猜错的抽象比没有抽象更难拆。等真要走路 B 时，照缝0/缝2 的方式现做即可。
