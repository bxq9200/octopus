# 护城河剥离设计（Phase A 补接线 + Phase B 剥离客户端包）

> 2026-07-23 规划。用户决定「做 A（做透）→ 再做 B」。今天只规划，明天照此执行。
> 目标：**agent 的秘密（prompt 工程）只在云端执行，桌面客户端包里不含可执行的 prompt。**

---

## 0. 一句话结论

缝0（`base_agent.run()/chat()` 的云端分叉）**几乎没生效**：executor 直接调 ~15 个 agent 方法，绕过 `run()`。要真护城河，必须让**所有含 prompt 的方法**都走云端（Phase A），然后把客户端 agent 换成壳（Phase B）。

- **缝0 只在 `run()`/`chat()` 分叉**；但 executor 大量 `self.<agent>.<method>()` 直接调，绕过 `run()`。只有 `chat()` 真走了云端。
- executor 实际调的 agent 方法（`interactive_executor.py`）：

## 2. 架构：`@cloud_method` 装饰器 + 通用方法 RPC

### 2.1 客户端装饰器（护城河唯一开关，放 `agent_runtime`，**不剥离**）
```python
def cloud_method(fn):
    @functools.wraps(fn)
    async def wrapper(self, *args, **kwargs):
        if should_run_remote():
            payload = _sanitize_args_for_cloud(args, kwargs)   # 图→公网URL
            return await agent_call(self.name, fn.__name__, payload["args"], payload["kwargs"])
        return await fn(self, *args, **kwargs)                  # local：跑真身（dev/云端服务器）
    return wrapper
```
- 给**每个 secret 方法**加 `@cloud_method`（execute + director/audio 的自定义 LLM 方法）。
- **local 模式（should_run_remote=False）跑真身 → dev / 云端服务器行为零变化、零回归。** 只有 cloud_client 客户端才路由。
- `chat()` 已有 base 分叉，保留不动（也可后续统一到装饰器）。

### 2.2 云端通用端点 `POST /v1/agent/call`（`cloud/`，local 模式跑真身）
```
body: {agent_type, method, args:[...], kwargs:{...}, llm_config:{...}}
→ agent = get_agent_class(agent_type)()
   with llm_override(llm_config):
       result = await getattr(agent, method)(*args, **kwargs)
→ {ok, data: result, usage?: agent._last_usage}
```
- 复用现有：`agent_registry.get_agent_class`、`llm_override`（缝0 已建）、`entitlements.require(AGENT_RUN)`、`cloud/main.py` 的 agent 加载。
- 与现有 `/v1/agent/run`（entry=execute/chat）并存或替换；建议**新增 `/v1/agent/call` 通用版**，`/v1/agent/run` 保留兼容。

### 2.3 客户端 RPC 助手 `agent_call(agent_type, method, args, kwargs)`
- 复用 `run_remote` 的一切（`cloud_http.post`、超时 600s、token、日志脱敏、`apply_usage`）。
- 只是 body 从 `{entry,payload}` 变成 `{method,args,kwargs}`。

## 3. 四个复杂点及解法

1. **图片参数 → 公网 URL**（refine_outline.attachments / review_art.art_direction 内图 URL / 待验 execute）：
   `_sanitize_args_for_cloud` 递归遍历 args/kwargs，凡是 `/output/...`、本地路径、data:URL 的图 → 走 `media_gateway.to_model_input(public=True)`（**平台 OSS 已建好，2026-07-23**）转公网 URL 再上云。云端 agent 直接拿 URL。
   - 起步可**按方法白名单指定要转的字段**（refine_outline→attachments、review_art→art_direction），比全递归稳。
2. **progress_cb（storyboard.execute）**：回调没法序列化。cloud 模式**丢细粒度进度**，装饰器在 RPC 前 emit 一条「☁️ 云端生成分镜中……」。未来增强 = 云端 SSE 流式回进度（Phase A 之外）。
3. **序列化**：已核 args/返回全是 dict/str/bool/list → JSON 安全。开工时对每个方法再确认一遍（尤其 execute 的 task 里别塞了不可序列化对象）。
4. **延迟**：非 LLM 方法（_extract_collected_info/on_node_confirmed/parse_script_file/route）**不加装饰器、留本地**（省往返、又非秘密）。LLM 方法本就慢，多一跳可接受。

## 4. Phase A 实施步骤（每步验证，不通不往下）

- **A1**：云端 `POST /v1/agent/call` 通用端点（`cloud/`）。本地起云端服务 + curl 验一个方法（如 detect_confirm_intent）。
- **A2**：客户端 `agent_runtime.agent_call()` + `cloud_method` 装饰器 + `_sanitize_args_for_cloud`。
- **A3**：给 6 个 execute + director 的 breakdown/detect/refine/review + audio 的 plan_* 加 `@cloud_method`。**router.route / _extract_collected_info / on_node_confirmed / parse_script_file 不加。**
- **A4**：executor 无需改调用点（装饰器透明）。但确认 executor 现在直接调的地方，装饰器都覆盖到了。
- **A5**：**全量端到端双跑（local 必须零回归 + cloud 必须真上云）**，逐阶段：对话路由 → 大纲协商(refine_outline,带图) → 分集(breakdown) → 编剧 → 美术 → review_art(带图) → 分镜(progress) → 音频 → 发布。cloud 侧查日志确认「agent 在云端跑、prompt 没下发」。
- **A6**：修 A5 暴露的回归，直到 local/cloud 两模式一集跑通。

## 5. Phase B 实施步骤（A 全绿后）

- **B1**：stub 生成器 `desktop/gen_agent_stubs.py`：读真 agent → 抽 `class XxxAgent(BaseAgent)` + `name` + 各 `@cloud_method` 方法签名 → 生成壳：
  - `@cloud_method` 方法 → 保留装饰器 + 签名，**body 换成 `pass`/`raise`**（cloud 模式永远路由，body 不跑）。
  - 留本地的非 LLM 方法（route/parse_script_file/…）→ **body 原样保留**（非秘密）。
  - system_prompt 类属性 → 清空占位。
- **B2**：打包从 **staging 副本**构建，真源码零改动：
  - `desktop/build_desktop.py`：`backend/` → `_build_stage/backend/`（复制）→ 用 stub 覆盖 `_build_stage/backend/app/agents/*/`_agent.py` → PyInstaller `pathex` 指 `_build_stage/backend`（spec 的 `BACKEND` 读 env `OCTOPUS_BUILD_BACKEND`）→ 构建 → 清理 staging。
- **B3**：验证 —— ①staging agent 是壳（体积骤降）②扒包/反编译抽查 storyboard/director .pyc **不含 prompt 明文**（pyinstxtractor+decompyle 抽一个）③打包版 cloud 模式跑一集，agent 真上云、无本地 prompt。

## 6. 风险与回滚

- **local 模式必须零回归**：装饰器在 `should_run_remote()=False` 时跑真身，dev/云端服务器完全不变。这是安全网 —— 任何时候出问题，切回 local 模式即恢复。
- **单一真源**：真 agent 永远是唯一源；壳是构建期从真源生成，不手维护第二份。
- **分步可停**：A1-A6 每步独立验证；B 在 A 全绿后才动。任一步坏了不影响已验的上一步。
- **云端服务器同步**：Phase A 改了 agent 装饰器（backend/app/agents/*），云端服务器也 import 这些（跑真身），要一并 deploy（`deploy_cloud.ps1` 或 scp agents + 重启 octopus-cloud）。
