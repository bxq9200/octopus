# 支付宝收款配置指引（公司主体）

> 代码已全部就绪并通过验证。**你只需要在支付宝那边办完手续，把 3 个凭据填到服务器上**，充值功能立刻生效。
> 在填之前，客户端点「充值」会显示「在线充值暂未开放，请联系客服」，不会报错。

---

## 一、支付宝那边要办的（约 1–3 天，多数时间在等审核）

### 1. 企业支付宝账号
用公司营业执照注册并完成实名认证（对公账户小额打款验证）。已有就跳过。

### 2. 创建应用
去 [open.alipay.com](https://open.alipay.com) → 控制台 → **网页&移动应用** → 创建应用
- 应用名称：Octopus
- 应用类型：网页应用

### 3. 签约「电脑网站支付」
在应用里 → 能力管理 → 添加能力 → **电脑网站支付** → 签约
需要填：
- **网站地址**：`https://<你的域名>`
- **ICP 备案号**：`<你的域名>` 的备案号（你已备案）
- 网站截图 / 经营内容说明

> 审核通常 1–3 个工作日。签约通过后这个能力才可用。

### 4. 配置密钥（RSA2）
在应用 → 开发设置 → 接口加签方式 → **公钥模式**
1. 用支付宝的[密钥生成工具](https://opendocs.alipay.com/common/02kipl)生成 **RSA2 (2048)** 密钥对
2. 把**应用公钥**粘贴到支付宝后台 → 保存后它会给你一个**支付宝公钥**
3. 你手上现在有：**应用私钥**（自己保管）+ **支付宝公钥**（从后台复制）

### 5. 设置回调地址（如果后台要求填）
- 授权回调 / 应用网关：`https://<你的域名>`
- 异步通知地址代码里已经带上了（`https://<你的域名>/v1/pay/notify`），一般不用在后台单独填

---

## 二、把 3 个凭据填到服务器（这一步告诉我，我来做；你也可以自己填）

SSH 到云端服务器，编辑 `/octopus/config/secrets.env`，加三行：

```bash
ALIPAY_APP_ID=2021xxxxxxxxxxxx
ALIPAY_PRIVATE_KEY=MIIEvgIBADANBgkq...        # 应用私钥，一整行，不要换行、不要 BEGIN/END 头尾
ALIPAY_PUBLIC_KEY=MIIBIjANBgkqhkiG9w0...      # 支付宝公钥，同样一整行
```

然后重启：`systemctl restart octopus-cloud`

验证：`curl https://api.<你的域名>/v1/pay/tiers` 里 `"enabled": true` 就是通了。

> ⚠️ **私钥就是钱**。别发到聊天工具/邮件/截图里。要给我的话，直接你自己填服务器最安全。

## 三、上线前务必做的：真实小额测试

配好之后**先自己充 ¥50 走一遍全流程**，确认：
1. 客户端点「充值」→ 浏览器打开支付宝收银台（金额正确）
2. 付款完成 → 浏览器跳到「支付完成」页
3. **回到 Octopus，余额自动增加 5000 credits**（这一步验证的是异步通知回调，最关键）
4. 去管理后台 `https://<你的域名>/admin` 看该用户的流水里有一条 `topup +5000`

**如果第 3 步没到账**，八成是异步通知没打进来。排查：
```bash
ssh root@<你的服务器> 'journalctl -u octopus-cloud -n 100 | grep "\[pay\]"'
```
- 看到「验签不通过」→ 公钥填错了（可能是把**应用公钥**当成**支付宝公钥**填了）
- 完全没有 `[pay]` 日志 → 支付宝没能访问到 `<你的域名>/v1/pay/notify`（检查安全组/域名解析）

## 五、代码侧已经做好的（供你了解）

- **订单表** `orders` + credits 流水 `credit_ledger`
- **到账只认异步通知**（return_url 上的参数可被伪造，不作数）
- **三重校验**：RSA2 验签 + app_id 匹配 + **金额与订单一致**（防改价攻击）
- **幂等**：支付宝会重复推送通知直到收到 `success`，靠 ledger 哨兵保证**只到账一次**
- **签名逻辑已用自生成密钥对做过往返测试**：正常签验通过、篡改金额被拒、无签名被拒、中文参数不破坏签名
